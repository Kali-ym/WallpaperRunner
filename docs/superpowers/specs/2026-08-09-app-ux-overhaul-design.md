# 套图库可用性与交互大升级 — 设计规格

日期：2026-08-09  
状态：已批准 / 已实施  
相关：既有 Telegram/Telegraph 渠道、库/下载/设置三页结构  
实施计划：`docs/superpowers/plans/2026-08-09-app-ux-overhaul.md`

## 1. 目标

将当前「功能堆叠的半成品」升级为**浅色、干净的桌面工具**：

1. **交互**：下载/设置/图库工作流拆清，降低误用与打断
2. **可视化反馈**：解析抽屉 + 缩略图、任务进度（百分比/速度/可展开明细）
3. **图库管理**：右键菜单、元信息可编辑
4. **压缩包**：下载完成后询问是否解压入库
5. **视觉**：按 `.agents/skills/redesign-existing-projects` 与 `design-taste-frontend-v1`，在现有 Electron + React + CSS 上升级（不推倒换栈）

## 2. 决策摘要

| 项 | 选择 |
| --- | --- |
| 交付方式 | 交互重构 + 视觉升级一轮做完 |
| 视觉基调 | 浅色干净工具风 |
| 解析 UI | 右侧抽屉 |
| 进度 | 任务级默认；可展开文件明细（百分比、速度、ETA） |
| 压缩包 | 下完后弹窗询问是否解压入库；首版 zip |
| 下载来源 | **用户显式选择**，程序不自动判断 URL 来源 |
| 来源解耦 | 每源独立适配模块 + 统一任务接口 |
| Telegram 多 URL | **合并为一套图**：一次粘贴多条 t.me 消息链接 → 同一图库目录 |
| 图库 | 右键菜单 + 元信息编辑（标题/作者/标签等） |

## 3. 信息架构

```
顶栏导航：库 | 下载 | 设置
├─ 库：浏览 / 搜索 / 右键与批量 / 编辑元信息 / 进入查看器
├─ 下载：来源选择 + URL → 队列主区；解析时右侧抽屉
└─ 设置：通用 | 网络 | Telegram | Wallpaper（分区，非一长卷）
```

- **库**：发现与管理，不承担下载表单
- **下载**：入队与进度；需勾选的来源走抽屉
- **设置**：配置与登录；Telegram 用短步骤条

全局：轻量 toast / 行内错误；空状态给引导；少用 `window.alert`。

## 4. 下载：显式来源与解耦

### 4.1 来源选择

下载页必选来源之一：

- `xChina`
- `Telegram`
- `Telegraph`

粘贴 URL 后由**当前选中来源**的适配器处理。URL 与来源不匹配时行内提示，不静默改派。

禁止：根据 URL 自动 `resolveAdapter` 作为主路径（可保留内部校验，但 UI 不靠自动猜源）。

### 4.2 模块边界

| 模块 | 职责 |
| --- | --- |
| `sources/xchina` | 解析分页、直入队、多图 HTTP 下载 |
| `sources/telegram` | 登录依赖、单条/多条 discover、抽屉勾选、MTProto 下载；**多 URL 合并为一套图** |
| `sources/telegraph` | discover（优先 TG 缓存）、抽屉勾选、下载 |
| `queue` | 统一任务状态、进度事件、取消；不关心站点细节 |

统一任务接口概念形状：

- `createTasks(input) → QueueTask[]` 或 `discover(input) → Manifest` + `enqueueSelected(...)`
- 进度：`done/total`、`percent`、`bytesPerSec`、`etaSec`、可选 `files[{ id, name, status, error }]`

### 4.3 右侧解析抽屉

- 「解析资源」打开约 420–480px 右抽屉
- 分组：主帖 / 评论 / Telegraph；批量按类型；缩略图（无则占位）
- **Telegram 多 URL**：抽屉内按「消息 1 / 消息 2 / …」再分子组（每条仍可含主帖/评论/Telegraph）；全选作用于合并后的全部资源
- 底栏：下载所选 (N) / 关闭；入队后收起
- Telegram 未登录等：抽屉内错误 + 链到设置

### 4.3.1 Telegram：多 URL 合并为一套图

当来源为 Telegram，且输入框内有**多条**消息 URL（换行或逗号分隔）时：

1. 视为**一次合并任务**，不是多套独立图库  
2. 对每条 URL 分别 discover，资源列表在抽屉中按消息分组展示  
3. 用户勾选后，**全部选中资源下载到同一个 gallery**  
4. 目录 / `galleryId`：稳定合并键，例如  
   `telegram_merge_{hash(sorted normalized urls)}`  
   或 `telegram_{channel}_{firstMsgId}_n{count}`（同一频道多帖时优先可读命名；跨频道用 merge hash）  
5. `metadata.sourceUrl`：可存主链接（第一条）或 URL 列表（JSON 数组字符串）；编辑信息时只读区展示「含 N 条消息」  
6. 队列：一个任务进度覆盖全部选中文件（可展开明细里带来源消息标签）  
7. 单条 URL 行为不变（一套图对应一条消息）

xChina / Telegraph 本轮**不**做多 URL 合并（多条仍按条处理或提示仅 Telegram 支持合并）；若误在其它来源粘贴多条，行内说明规则。

### 4.4 队列进度

- 默认行：标题、状态、进度条、百分比、速度、ETA、取消
- 展开：每文件完成/失败/进行中 + 短错误
- xChina 多图与 TG 多资源共用同一套进度 UI

### 4.5 压缩包询问解压

- 首版：`zip`
- 任务成功且产物为 zip 时弹窗：「解压图片入库」/「仅保留压缩包」
- 解压扫描常见图片扩展名 → 一套图入库；默认保留 zip；失败可重试且不丢文件

## 5. 图库

### 5.1 右键菜单

卡片上：打开、编辑信息、收藏/取消、打开文件夹、重新下载、删除。  
多选时对选中项批量收藏/删除。

顶栏收敛：搜索、仅收藏、多选、数量；「清理空壳」进溢出或空白处菜单。

### 5.2 元信息编辑

可编辑：`displayTitle`（或展示标题）、`author`、`tags`。  
只读：`source`、`galleryId`、`sourceUrl`。  
写回 `metadata.json` 并更新 `library.json` 索引。

## 6. 设置

四段分区卡片/手风琴：

1. 通用：下载目录、套内并发  
2. 网络：代理  
3. Telegram：状态徽章 + 步骤（凭证 → 手机 → 验证码/2FA → 完成）  
4. Wallpaper Engine：现有能力归组  

保存用 toast。

## 7. 视觉规范（浅色工具）

- 中性浅底 + 单一强调色（克制饱和度；禁止紫蓝 AI 渐变风）
- 工具向 sans（如 Geist / Outfit）+ 进度数字 tabular/等宽
- 少滥用大卡片；列表分割与浅底分区；抽屉/模态层级清晰、可见 focus
- 动效克制：抽屉、进度、hover/active
- 加载：库网格与抽屉列表用骨架屏；空状态有文案与主操作

技术约束：保持 Electron + React + 现有 CSS 体系升级；引入字体/图标需显式安装依赖；不默认上 Tailwind，除非实施计划另行批准。

## 8. 非目标（本轮不做）

- 多窗口拆分（独立队列窗等）
- rar/7z 解压（可列为后续）
- 自动 URL 来源探测作为主交互
- 深色主题（可后续「跟随系统」）
